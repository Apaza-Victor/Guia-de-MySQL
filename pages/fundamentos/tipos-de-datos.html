Tipos de datos en MySQL

MySQL ofrece una amplia variedad de tipos de datos que permiten almacener información de forma eficiente y precisa. Elegir el tipo de dato correcto es fundamental para garantizar la integridad de los datos, optimizar el rendimiento de las consultas y minimizar el espacio de almacenamiento. Cada tipo tiene un rango específico de valores y un tamaño en bytes que debe considerarse al diseñar tablas.

Tipos numéricos

Los tipos numéricos se dividen en enteros (INT, TINYINT, SMALLINT, MEDIUMINT, BIGINT) y decimales (DECIMAL, FLOAT, DOUBLE). Los enteros almacenan números sin parte fraccionaria, mientras que DECIMAL es ideal para valores exactos como precios y cantidades monetarias. FLOAT y DOUBLE almacenan números de punto flotante con precisión aproximada.

Ejemplo con tipos numéricos

SQL
CREATE TABLE productos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100),
    precio DECIMAL(10,2),
    stock SMALLINT DEFAULT 0,
    peso_kg FLOAT
);

INSERT INTO productos (nombre, precio, stock, peso_kg)
VALUES ('Laptop Gamer', 1299.99, 25, 2.5);

Tipos de cadena

Para almacenar texto, MySQL ofrece CHAR (longitud fija), VARCHAR (longitud variable hasta 65535 caracteres), TEXT (hasta 65535 caracteres), MEDIUMTEXT y LONGTEXT. CHAR es más rápido para longitudes fijas como códigos, mientras que VARCHAR ahorra espacio en cadenas de longitud variable. BLOB se usa para datos binarios como imágenes o archivos.

Ejemplo con tipos de cadena

SQL
CREATE TABLE empleados (
    id INT AUTO_INCREMENT PRIMARY KEY,
    codigo CHAR(8) UNIQUE,
    nombre_completo VARCHAR(150),
    biografia TEXT,
    foto_perfil BLOB
);

INSERT INTO empleados (codigo, nombre_completo, biografia)
VALUES ('EMP-0001', 'María García López', 'Ingeniera de sistemas con 10 años de experiencia en bases de datos.');

Tipos de fecha y hora

MySQL dispone de cinco tipos para fechas y horas: DATE (solo fecha, formato YYYY-MM-DD), TIME (solo hora), DATETIME (fecha y hora combinadas), TIMESTAMP (similar a DATETIME pero con zona horaria) y YEAR (solo el año). TIMESTAMP tiene un rango menor (1970-2038) pero ocupa menos espacio.

Ejemplo con tipos de fecha

SQL
CREATE TABLE pedidos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    fecha_creacion DATETIME DEFAULT CURRENT_TIMESTAMP,
    fecha_entrega DATE,
    hora_estimada TIME,
    anio_pedido YEAR
);

INSERT INTO pedidos (fecha_entrega, hora_estimada, anio_pedido)
VALUES ('2026-08-15', '14:30:00', 2026);

Tipos especiales: ENUM, SET, JSON, GEOMETRY

ENUM permite definir una columna con un conjunto fijo de valores posibles (como 'Activo', 'Inactivo'). SET es similar pero permite múltiples valores simultáneamente. JSON almacena documentos JSON de forma nativa con validación automática. GEOMETRY y sus subtipos (POINT, LINESTRING, POLYGON) almacenan datos espaciales para sistemas de información geográfica.

Ejemplo con tipos especiales

SQL
CREATE TABLE clientes (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100),
    estado ENUM('Activo', 'Inactivo', 'Suspendido') DEFAULT 'Activo',
    intereses SET('Deportes', 'Tecnología', 'Moda', 'Viajes'),
    metadata JSON,
    ubicacion POINT
);

INSERT INTO clientes (nombre, estado, intereses, metadata)
VALUES ('Carlos Ruiz', 'Activo', 'Tecnología,Viajes', '{"fidelidad": "oro", "visitas": 45}');

Usa DECIMAL para valores monetarios en lugar de FLOAT o DOUBLE, ya que estos últimos tienen errores de redondeo que pueden causar discrepancias en cálculos financieros.

El tipo TIMESTAMP tiene un rango limitado hasta 2038. Para aplicaciones que necesiten fechas más allá de ese año, usa DATETIME que soporta hasta el año 9999.

Siempre elige el tipo de dato más pequeño que pueda almacenar tus datos. Por ejemplo, usa TINYINT en lugar de INT si sabes que los valores no superarán 127. Esto reduce el espacio en disco y mejora el rendimiento de las consultas.
