ORDER BY y LIMIT

Las cláusulas ORDER BY y LIMIT permiten controlar la presentación y cantidad de los resultados. Con ORDER BY se define el criterio de ordenamiento, y con LIMIT se restringe el número de filas devueltas. Son fundamentales para crear reportes ordenados, implementar paginación y obtener los registros más relevantes, como los primeros o últimos según algún criterio.

Datos de ejemplo: productos

Para esta lección usaremos una tabla productos con artículos de inventario, incluyendo nombre, precio y existencias.

SQL
CREATE TABLE productos (
  id INT PRIMARY KEY AUTO_INCREMENT,
  nombre VARCHAR(60),
  precio DECIMAL(10,2),
  stock INT
);

INSERT INTO productos VALUES
(1, 'Laptop', 15000.00, 10),
(2, 'Mouse', 250.00, 50),
(3, 'Teclado', 800.00, 30),
(4, 'Monitor', 4500.00, 15),
(5, 'Audífonos', 600.00, 25),
(6, 'Webcam', 1200.00, 8);

ORDER BY ASC y DESC

Por defecto, ORDER BY ordena de forma ascendente (ASC). Para orden descendente se usa DESC. Es posible ordenar por cualquier columna, incluyendo aquellas que no aparecen en la lista de selección. El ordenamiento se aplica después de que se han evaluado todas las condiciones del WHERE.

SQL
SELECT nombre, precio FROM productos ORDER BY precio DESC;
nombreprecio
Laptop15000.00
Monitor4500.00
Webcam1200.00
Teclado800.00
Audífonos600.00
Mouse250.00

ORDER BY con múltiples columnas

Se puede ordenar por varias columnas separándolas con comas. La primera columna tiene prioridad; en caso de empate, se usa la segunda, y así sucesivamente. A cada columna se le puede indicar ASC o DESC de forma independiente, lo que permite crear ordenamientos complejos como "ordenar por departamento ascendente y salario descendente".

SQL
SELECT nombre, precio, stock FROM productos ORDER BY stock ASC, precio DESC;
nombrepreciostock
Webcam1200.008
Laptop15000.0010
Monitor4500.0015
Audífonos600.0025
Teclado800.0030
Mouse250.0050

LIMIT para restringir resultados

La cláusula LIMIT especifica el número máximo de filas que devolverá la consulta. Se coloca al final de la sentencia, después de ORDER BY si existe. Es muy útil para obtener los "top N" registros, como los productos más caros o los empleados con mayor antigüedad.

SQL
SELECT nombre, precio FROM productos ORDER BY precio DESC LIMIT 3;
nombreprecio
Laptop15000.00
Monitor4500.00
Webcam1200.00

LIMIT con OFFSET para paginación

La sintaxis LIMIT n OFFSET m permite saltar las primeras m filas y devolver las siguientes n. Esto es la base para implementar paginación en aplicaciones web. Por ejemplo, para mostrar 2 productos por página: página 1 sería LIMIT 2 OFFSET 0, página 2 sería LIMIT 2 OFFSET 2, y así sucesivamente. También existe la sintaxis abreviada LIMIT m, n donde m es el offset y n es el límite.

SQL
SELECT nombre, precio FROM productos ORDER BY precio ASC LIMIT 2 OFFSET 2;
nombreprecio
Teclado800.00
Mouse250.00

Combinación con WHERE

WHERE, ORDER BY y LIMIT se pueden combinar en una misma consulta. El orden de las cláusulas es estricto: primero WHERE, luego ORDER BY y finalmente LIMIT. Esto permite filtrar, ordenar y limitar los resultados en un solo paso.

SQL
SELECT nombre, precio, stock FROM productos WHERE stock > 10 ORDER BY precio DESC LIMIT 2;
nombrepreciostock
Monitor4500.0015
Teclado800.0030

Para paginación eficiente en tablas grandes, combina LIMIT con OFFSET o usa la sintaxis abreviada LIMIT offset, cantidad. Sin embargo, para conjuntos de datos muy grandes, considera alternativas como WHERE id > último_id que son más eficientes que OFFSET.

Sin ORDER BY, el orden de los resultados no está garantizado. MySQL puede devolver las filas en cualquier orden, especialmente cuando los datos cambian. Siempre usa ORDER BY si necesitas un orden específico.
