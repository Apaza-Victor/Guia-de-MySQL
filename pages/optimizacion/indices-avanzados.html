Índices avanzados y covering index

Más allá del índice simple de una columna, MySQL ofrece estrategias avanzadas como índices compuestos, covering indexes, índices funcionales e índices parciales. Usados correctamente, pueden eliminar por completo las lecturas a la tabla y reducir el tiempo de las consultas a microsegundos.

Índices compuestos (multi-columna)

Un índice compuesto abarca varias columnas. El orden de las columnas es crítico: MySQL puede usar el índice solo si las condiciones empiezan por la primera columna del índice (regla del prefijo más a la izquierda).

SQL — Creación de índice compuesto
CREATE INDEX idx_pais_ciudad ON clientes(pais, ciudad, activo);

-- ✅ Usa el índice completamente (todas las columnas)
SELECT * FROM clientes WHERE pais = 'MX' AND ciudad = 'CDMX' AND activo = 1;

-- ✅ Usa el índice parcialmente (primeras 2 columnas)
SELECT * FROM clientes WHERE pais = 'MX' AND ciudad = 'CDMX';

-- ✅ Usa el índice parcialmente (solo primera columna)
SELECT * FROM clientes WHERE pais = 'MX';

-- ❌ No usa el índice (falta la primera columna)
SELECT * FROM clientes WHERE ciudad = 'CDMX' AND activo = 1;

Covering Index (índice de cobertura)

Un covering index contiene todas las columnas que necesita la consulta. MySQL puede resolverla enteramente desde el índice sin tocar la tabla (filas de datos). En EXPLAIN se ve como Extra: Using index.

SQL — Creando un covering index
-- Consulta que solo pide id, nombre y email
EXPLAIN SELECT id, nombre, email FROM clientes WHERE pais = 'MX';
-- Si el índice cubre estas 3 columnas → Extra: Using index

-- Índice compuesto que cubre toda la consulta
CREATE INDEX idx_covering ON clientes(pais, id, nombre, email);

Cuando el índice cubre la consulta, MySQL evita la lectura de páginas de datos (clustered index), lo que reduce drásticamente las operaciones de I/O.

Índices con funciones (MySQL 8.0.13+)

MySQL 8.0.13+ permite indexar expresiones y funciones. Esto resuelve el problema de las consultas no sargables sin alterar la aplicación.

SQL — Índice funcional
-- Índice funcional sobre expresión LOWER
CREATE INDEX idx_lower_email ON clientes((LOWER(email)));

-- Ahora esta consulta puede usar el índice
SELECT * FROM clientes WHERE LOWER(email) = 'usuario@example.com';

Índices parciales (column index prefix)

Para columnas VARCHAR largas, puedes indexar solo los primeros N caracteres, ahorrando espacio y mejorando la velocidad de inserción.

SQL — Índice parcial
-- Índice solo sobre los primeros 10 caracteres
CREATE INDEX idx_desc_corta ON productos(descripcion(10));

-- Útil para LIKE con prefijo
SELECT * FROM productos WHERE descripcion LIKE 'laptop%';

Estadísticas de índices

MySQL usa estadísticas para decidir si usar un índice. Con el tiempo, las estadísticas se desactualizan. Puedes actualizarlas con ANALYZE TABLE.

SQL — Mantenimiento de estadísticas
-- Ver estadísticas de índices
SHOW INDEX FROM clientes;

-- Actualizar estadísticas
ANALYZE TABLE clientes;

-- Ver tamaño y cardinalidad de índices
SELECT TABLE_NAME, INDEX_NAME, CARDINALITY, SEQ_IN_INDEX
FROM INFORMATION_SCHEMA.STATISTICS
WHERE TABLE_SCHEMA = 'midb';

En índices compuestos, coloca primero la columna con mayor cardinalidad (más valores distintos). Así MySQL reduce más rápido el conjunto de resultados. Ejemplo: en INDEX(pais, genero, fecha), pais suele tener más valores distintos que genero.

Cada índice adicional ralentiza INSERT, UPDATE y DELETE porque hay que mantenerlo sincronizado. No indexes todas las columnas "por si acaso". Usa EXPLAIN para identificar los índices que realmente necesitas y elimina los duplicados o infrautilizados.
