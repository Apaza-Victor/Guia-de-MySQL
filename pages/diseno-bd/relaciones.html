Tipos de relaciones en BD

En las bases de datos relacionales, las relaciones definen cómo se asocian las tablas entre sí. Los tres tipos fundamentales son 1:1 (uno a uno), 1:N (uno a muchos) y N:M (muchos a muchos). Cada una se implementa de forma distinta usando claves foráneas.

Relación 1:1 (Uno a uno)

Cada fila de la tabla A se relaciona con exactamente una fila de la tabla B, y viceversa. Se implementa colocando una FK única en una de las tablas. Ejemplo: un usuario tiene un perfil, y un perfil pertenece a un solo usuario.

SQL
CREATE TABLE usuario (
    id_usuario INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(30) NOT NULL UNIQUE
);

CREATE TABLE perfil (
    id_perfil INT AUTO_INCREMENT PRIMARY KEY,
    bio TEXT,
    avatar_url VARCHAR(255),
    id_usuario INT UNIQUE NOT NULL,
    FOREIGN KEY (id_usuario) REFERENCES usuario(id_usuario)
);

Relación 1:N (Uno a muchos)

Una fila de la tabla A puede relacionarse con varias filas de la tabla B, pero cada fila de B se relaciona con solo una fila de A. Es el tipo más común. Se implementa colocando la FK en la tabla "muchos". Ejemplo: una categoría contiene varios productos.

SQL
CREATE TABLE categoria (
    id_categoria INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(50) NOT NULL
);

CREATE TABLE producto (
    id_producto INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    precio DECIMAL(10,2) NOT NULL,
    id_categoria INT NOT NULL,
    FOREIGN KEY (id_categoria) REFERENCES categoria(id_categoria)
);

Relación N:M (Muchos a muchos)

Una fila de la tabla A puede relacionarse con varias filas de la tabla B, y viceversa. Se implementa mediante una tabla intermedia (o tabla pivote) que contiene las FK de ambas tablas. Ejemplo: estudiantes se inscriben en cursos; un estudiante puede cursar varios cursos y un curso tiene varios estudiantes.

SQL
CREATE TABLE estudiante (
    id_estudiante INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL
);

CREATE TABLE curso (
    id_curso INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    creditos INT NOT NULL
);

-- Tabla intermedia para la relación N:M
CREATE TABLE inscripcion (
    id_estudiante INT NOT NULL,
    id_curso INT NOT NULL,
    fecha_inscripcion DATE NOT NULL,
    PRIMARY KEY (id_estudiante, id_curso),
    FOREIGN KEY (id_estudiante) REFERENCES estudiante(id_estudiante),
    FOREIGN KEY (id_curso) REFERENCES curso(id_curso)
);

La tabla intermedia en relaciones N:M puede incluir atributos adicionales como fecha_inscripcion, calificación o semestre. La clave primaria suele ser compuesta (ambas FK) o puedes agregar un id_inscripcion autoincremental como PK simple.
