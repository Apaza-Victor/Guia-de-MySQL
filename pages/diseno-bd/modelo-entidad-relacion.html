Modelo Entidad-Relación (ER)

El modelo Entidad-Relación (ER) es una herramienta de diseño conceptual que representa la estructura lógica de una base de datos mediante entidades, atributos y relaciones. Fue propuesto por Peter Chen en 1976 y sigue siendo el estándar para modelar datos antes de implementarlos en un SGBD relacional.

¿Qué es una entidad?

Una entidad es un objeto del mundo real con existencia propia que puede identificarse de forma única. Se representa como un rectángulo en el diagrama ER. Ejemplos: Libro, Autor, Socio, Préstamo.

Atributos

Los atributos son las propiedades que describen a una entidad. Se representan como óvalos conectados a su entidad. Pueden ser simples (único valor) o compuestos (varios componentes), monovaluados o multivaluados, y derivados (calculados a partir de otros).

Relaciones y cardinalidad

Una relación es una asociación entre dos o más entidades. Se representa con un rombo. La cardinalidad define cuántas instancias de una entidad pueden asociarse con otra:

  • 1:1 (uno a uno): Un socio tiene un único carnet. Un carnet pertenece a un solo socio.
  • 1:N (uno a muchos): Un autor puede escribir varios libros. Un libro es escrito por un solo autor (en este modelo simplificado).
  • N:M (muchos a muchos): Un libro puede tener varios autores y un autor puede escribir varios libros. Requiere tabla intermedia.

Ejemplo: Sistema de Biblioteca

Modelamos un sistema de biblioteca con las entidades Libro, Autor, Socio y Préstamo. La relación escribe vincula Autor con Libro (1:N). La relación realiza vincula Socio con Préstamo (1:N). La relación incluye vincula Préstamo con Libro (1:N).

SQL
CREATE DATABASE biblioteca;
USE biblioteca;

CREATE TABLE autor (
    id_autor INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(50) NOT NULL,
    apellido VARCHAR(50) NOT NULL,
    nacionalidad VARCHAR(30)
);

CREATE TABLE libro (
    isbn VARCHAR(13) PRIMARY KEY,
    titulo VARCHAR(100) NOT NULL,
    anio_publicacion YEAR,
    genero VARCHAR(30),
    id_autor INT NOT NULL,
    FOREIGN KEY (id_autor) REFERENCES autor(id_autor)
);

CREATE TABLE socio (
    id_socio INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(50) NOT NULL,
    direccion VARCHAR(150),
    telefono VARCHAR(15),
    email VARCHAR(100) UNIQUE
);

CREATE TABLE prestamo (
    id_prestamo INT AUTO_INCREMENT PRIMARY KEY,
    fecha_inicio DATE NOT NULL,
    fecha_devolucion DATE,
    estado ENUM('activo', 'devuelto', 'vencido') DEFAULT 'activo',
    id_socio INT NOT NULL,
    isbn VARCHAR(13) NOT NULL,
    FOREIGN KEY (id_socio) REFERENCES socio(id_socio),
    FOREIGN KEY (isbn) REFERENCES libro(isbn)
);

Puedes dibujar diagramas ER gratis con herramientas como draw.io, dbdiagram.io o Lucidchart. dbdiagram.io además genera el código SQL automáticamente a partir del diagrama.

El modelo ER es independiente del SGBD. Puedes diseñarlo sin pensar en MySQL, PostgreSQL u otros. Luego lo transformas en un modelo relacional (tablas, claves, etc.) para implementarlo.
