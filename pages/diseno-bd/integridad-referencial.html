Integridad referencial y restricciones

La integridad de datos se refiere a la exactitud, consistencia y confiabilidad de los datos almacenados. MySQL proporciona diversos mecanismos para garantizar la integridad a nivel de base de datos mediante constraints (restricciones).

Integridad de entidad

Asegura que cada fila de una tabla sea única e identificable. Se logra mediante la PRIMARY KEY y la restricción UNIQUE. Garantiza que no existan filas duplicadas y que cada registro tenga un identificador inequívoco.

SQL
CREATE TABLE cliente (
    id_cliente INT AUTO_INCREMENT PRIMARY KEY,  -- Integridad de entidad
    codigo VARCHAR(10) UNIQUE NOT NULL,          -- Otra clave candidata
    nombre VARCHAR(100) NOT NULL
);

Integridad referencial

Garantiza que las relaciones entre tablas se mantengan consistentes. Se implementa mediante FOREIGN KEY. Una FK asegura que un valor en una columna hija siempre exista en la columna padre. Si intentas violar esta regla, MySQL rechaza la operación.

SQL
CREATE TABLE pedido (
    id_pedido INT AUTO_INCREMENT PRIMARY KEY,
    fecha DATE NOT NULL,
    id_cliente INT NOT NULL,
    FOREIGN KEY (id_cliente) REFERENCES cliente(id_cliente)
        ON DELETE RESTRICT
        ON UPDATE CASCADE
);

-- Esto funciona si el cliente 1 existe
INSERT INTO pedido (fecha, id_cliente) VALUES ('2025-03-01', 1);

-- Esto falla: "Cannot add or update a child row: a foreign key constraint fails"
INSERT INTO pedido (fecha, id_cliente) VALUES ('2025-03-01', 999);

Restricción CHECK

Valida que los valores de una columna cumplan una condición booleana. MySQL 8.0+ soporta CHECK constraints completamente. Antes se parseaban pero no se ejecutaban.

SQL
CREATE TABLE empleado (
    id_empleado INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    salario DECIMAL(10,2) CHECK (salario > 0),
    edad INT CHECK (edad >= 18 AND edad <= 70),
    tipo ENUM('tiempo_completo', 'medio_tiempo', 'freelance') DEFAULT 'tiempo_completo'
);

-- CHECK también puede tener nombre
CREATE TABLE producto (
    id_producto INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    precio DECIMAL(10,2) NOT NULL,
    stock INT NOT NULL,
    CONSTRAINT chk_precio_positivo CHECK (precio > 0),
    CONSTRAINT chk_stock_no_negativo CHECK (stock >= 0)
);

Restricción DEFAULT

Asigna un valor por defecto a una columna cuando no se especifica un valor en el INSERT. Mejora la consistencia al asegurar que ciertas columnas siempre tengan un valor predecible.

SQL
CREATE TABLE tarea (
    id_tarea INT AUTO_INCREMENT PRIMARY KEY,
    titulo VARCHAR(100) NOT NULL,
    descripcion TEXT,
    completada BOOLEAN DEFAULT FALSE,
    fecha_creacion DATE DEFAULT (CURRENT_DATE),
    prioridad ENUM('baja', 'media', 'alta') DEFAULT 'media'
);

INSERT INTO tarea (titulo, descripcion) 
VALUES ('Comprar insumos', 'Comprar papel y tinta');

-- Resultado: completada = FALSE, fecha_creacion = 2025-07-29, prioridad = 'media'

Restricción NOT NULL

Obliga a que una columna siempre tenga un valor. Es la restricción más básica pero una de las más importantes. Sin NOT NULL, una columna acepta NULL por defecto.

SQL
CREATE TABLE articulo (
    id_articulo INT AUTO_INCREMENT PRIMARY KEY,
    titulo VARCHAR(200) NOT NULL,       -- No puede ser NULL
    contenido TEXT NOT NULL,             -- No puede ser NULL
    resumen TEXT,                        -- Puede ser NULL
    fecha_publicacion DATE
);

-- Error: "Column 'titulo' cannot be null"
INSERT INTO articulo (titulo, contenido) VALUES (NULL, 'Contenido');

Verificar constraints existentes

SQL
-- Ver constraints de una tabla
SELECT TABLE_NAME, CONSTRAINT_NAME, CONSTRAINT_TYPE
FROM INFORMATION_SCHEMA.TABLE_CONSTRAINTS
WHERE TABLE_SCHEMA = 'mi_bd' AND TABLE_NAME = 'empleado';

-- Ver CHECK constraints específicamente
SELECT CONSTRAINT_NAME, CHECK_CLAUSE
FROM INFORMATION_SCHEMA.CHECK_CONSTRAINTS
WHERE CONSTRAINT_SCHEMA = 'mi_bd';

Planifica todas las restricciones (PK, FK, CHECK, DEFAULT, NOT NULL) antes de insertar datos masivos. Agregar constraints sobre tablas con millones de filas puede ser muy lento y bloquear la tabla durante la validación. Diseña primero, implementa después.
