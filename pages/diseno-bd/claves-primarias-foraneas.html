Claves primarias y foráneas

Las claves son el mecanismo fundamental para identificar filas de forma única y establecer relaciones entre tablas. En MySQL contamos con varios tipos de restricciones de clave que garantizan la integridad de los datos.

PRIMARY KEY

La clave primaria identifica de forma única cada fila de una tabla. No puede contener NULL y solo puede existir una por tabla. Puede ser simple (una columna) o compuesta (varias columnas).

SQL
-- Clave primaria simple
CREATE TABLE departamento (
    id_depto INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(50) NOT NULL
);

-- Clave primaria compuesta
CREATE TABLE detalle_pedido (
    id_pedido INT,
    id_producto INT,
    cantidad INT NOT NULL,
    precio DECIMAL(10,2) NOT NULL,
    PRIMARY KEY (id_pedido, id_producto)
);

AUTO_INCREMENT

Genera valores numéricos secuenciales automáticamente. Se usa normalmente con PRIMARY KEY para crear identificadores únicos. Por defecto empieza en 1 y se incrementa en 1.

SQL
CREATE TABLE usuario (
    id_usuario INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(30) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL UNIQUE
);

-- Insertar sin especificar el id
INSERT INTO usuario (username, email) VALUES
    ('jperez', 'jperez@mail.com'),
    ('mlopez', 'mlopez@mail.com');

-- MySQL asigna id_usuario = 1, 2 automáticamente

UNIQUE

Asegura que todos los valores en una columna (o combinación de columnas) sean distintos. A diferencia de PRIMARY KEY, permite múltiples restricciones UNIQUE por tabla y acepta valores NULL (un NULL no se considera igual a otro NULL).

SQL
CREATE TABLE empleado (
    id_empleado INT AUTO_INCREMENT PRIMARY KEY,
    codigo_empleado VARCHAR(10) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    nombre VARCHAR(50) NOT NULL
);

FOREIGN KEY

Una clave foránea vincula una columna de una tabla con la PRIMARY KEY de otra tabla, estableciendo una relación y garantizando la integridad referencial. Las acciones referenciales definen qué sucede al borrar o actualizar la fila padre:

  • ON DELETE CASCADE: Borra en cascada las filas hijas cuando se borra la fila padre.
  • ON DELETE RESTRICT: Impide borrar la fila padre si existen filas hijas (por defecto).
  • ON DELETE SET NULL: Establece la FK a NULL cuando se borra la fila padre.
  • ON UPDATE CASCADE: Propaga cambios en la clave padre a las filas hijas.
SQL
CREATE TABLE categoria (
    id_categoria INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(50) NOT NULL
);

CREATE TABLE producto (
    id_producto INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    precio DECIMAL(10,2) NOT NULL,
    id_categoria INT,
    FOREIGN KEY (id_categoria) REFERENCES categoria(id_categoria)
        ON DELETE RESTRICT
        ON UPDATE CASCADE
);

-- Ejemplo con ON DELETE CASCADE
CREATE TABLE factura (
    id_factura INT AUTO_INCREMENT PRIMARY KEY,
    fecha DATE NOT NULL
);

CREATE TABLE linea_factura (
    id_linea INT AUTO_INCREMENT PRIMARY KEY,
    id_factura INT NOT NULL,
    producto VARCHAR(100) NOT NULL,
    cantidad INT NOT NULL,
    FOREIGN KEY (id_factura) REFERENCES factura(id_factura)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);

Agregar y eliminar claves sobre tablas existentes

SQL
-- Agregar PRIMARY KEY
ALTER TABLE tabla ADD PRIMARY KEY (columna);

-- Agregar FOREIGN KEY
ALTER TABLE tabla ADD CONSTRAINT fk_nombre
    FOREIGN KEY (columna) REFERENCES otra_tabla(columna);

-- Agregar UNIQUE
ALTER TABLE tabla ADD CONSTRAINT uq_nombre UNIQUE (columna);

-- Eliminar restricciones
ALTER TABLE tabla DROP PRIMARY KEY;
ALTER TABLE tabla DROP FOREIGN KEY fk_nombre;
ALTER TABLE tabla DROP INDEX uq_nombre;

Usa nombres descriptivos para tus constraints: fk_producto_categoria, uq_usuario_email. Así será más fácil identificarlos cuando necesites eliminarlos o depurar errores.

Error común: "Cannot add or update a child row: a foreign key constraint fails". Ocurre cuando intentas insertar un valor en la FK que no existe en la tabla padre. Siempre verifica que los datos referenciados existan antes de insertar.
