Búsqueda de texto completo

La búsqueda de texto completo (Full-Text Search) permite localizar documentos que contengan palabras o frases específicas, con soporte para relevancia, exclusiones y comodines. Se basa en el índice FULLTEXT y la función MATCH()...AGAINST().

Qué es FULLTEXT INDEX

Un índice FULLTEXT está diseñado para columnas de tipo CHAR, VARCHAR o TEXT. Construye una lista de palabras (tokens) ignorando las llamadas stopwords y permite buscar por relevancia en lugar de simples coincidencias.

SQL
-- Crear tabla con índice FULLTEXT
CREATE TABLE articulos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    titulo VARCHAR(200) NOT NULL,
    contenido TEXT NOT NULL,
    autor VARCHAR(100),
    publicado DATE,
    FULLTEXT INDEX ft_articulos (titulo, contenido)
);

-- También se puede agregar después
-- CREATE FULLTEXT INDEX ft_articulos ON articulos(titulo, contenido);

MATCH...AGAINST en modo natural

El modo natural (predeterminado) devuelve los resultados ordenados por relevancia. Cuantas más veces aparezca el término y cuanto menos frecuente sea en el conjunto de documentos, mayor será la puntuación.

SQL
-- Búsqueda en modo natural
SELECT id, titulo, MATCH(titulo, contenido) AGAINST('índices rendimiento') AS relevancia
FROM articulos
WHERE MATCH(titulo, contenido) AGAINST('índices rendimiento')
ORDER BY relevancia DESC;

-- La columna relevancia es opcional; se puede usar solo el filtro
SELECT id, titulo FROM articulos
WHERE MATCH(titulo, contenido) AGAINST('optimización consultas');

Modo booleano

El modo booleano ofrece operadores para afinar la búsqueda: + (obligatorio), - (excluir), * (comodín), "" (frase exacta), entre otros.

SQL
-- Debe contener "MySQL" y no puede contener "Oracle"
SELECT * FROM articulos
WHERE MATCH(titulo, contenido) AGAINST('+MySQL -Oracle' IN BOOLEAN MODE);

-- Frase exacta "alta disponibilidad"
SELECT * FROM articulos
WHERE MATCH(titulo, contenido) AGAINST('"alta disponibilidad"' IN BOOLEAN MODE);

-- Comodín: palabras que empiecen con "optim"
SELECT * FROM articulos
WHERE MATCH(titulo, contenido) AGAINST('optim*' IN BOOLEAN MODE);

-- Combinación de operadores
SELECT * FROM articulos
WHERE MATCH(titulo, contenido) AGAINST('+rendimiento -lento +"base de datos"' IN BOOLEAN MODE);

Query expansion

La búsqueda con query expansion (WITH QUERY EXPANSION) realiza dos pasos: primero busca con el término original y luego agrega palabras relevantes de los documentos encontrados para la segunda ronda. Útil para refinar resultados cuando el término es muy específico.

SQL
-- Query expansion: encuentra documentos relacionados aunque no contengan el término exacto
SELECT id, titulo FROM articulos
WHERE MATCH(titulo, contenido) AGAINST('índices' WITH QUERY EXPANSION);

Límites y configuración

MySQL ignora palabras demasiado cortas o demasiado frecuentes. Los umbrales se controlan con variables del sistema.

SQL
-- Ver longitud mínima de palabra para FULLTEXT (InnoDB: 3, MyISAM: 4)
SHOW VARIABLES LIKE 'innodb_ft_min_token_size';
SHOW VARIABLES LIKE 'ft_min_word_len';

-- Lista de stopwords (palabras ignoradas)
SHOW VARIABLES LIKE 'innodb_ft_server_stopword_table';

-- Para modificar el tamaño mínimo (requiere reinicio)
-- En my.cnf o my.ini agregar:
-- [mysqld]
-- innodb_ft_min_token_size=2
-- ft_min_word_len=2

Ejemplo práctico: buscar artículos por contenido

Supongamos un blog de tecnología con miles de artículos. Con FULLTEXT los lectores encuentran contenido relevante al instante.

SQL
-- Insertar datos de ejemplo
INSERT INTO articulos (titulo, contenido, autor, publicado) VALUES
('Introducción a MySQL', 'MySQL es un sistema de gestión de bases de datos relacional...', 'Ana López', '2025-01-15'),
('Índices avanzados', 'Los índices B-tree y hash mejoran el rendimiento de las consultas...', 'Carlos Paz', '2025-02-20'),
('Optimización de consultas', 'Usar EXPLAIN para analizar el plan de ejecución...', 'Ana López', '2025-03-10');

-- Buscar artículos sobre índices que no hablen de hash
SELECT titulo, autor, publicado
FROM articulos
WHERE MATCH(titulo, contenido) AGAINST('+índices -hash' IN BOOLEAN MODE);

Introducción a MySQLAna López2025-01-15

FULLTEXT es radicalmente distinto a LIKE '%texto%'. LIKE escanea toda la tabla y no entiende de relevancia, sinónimos ni ranking. FULLTEXT usa un índice inverso, ordena por relevancia y es órdenes de magnitud más rápido en conjuntos grandes. Siempre que necesites búsqueda textual, usa FULLTEXT en lugar de LIKE.
