Motores de almacenamiento

MySQL ofrece distintos motores de almacenamiento (storage engines) que determinan cómo se almacenan los datos, cómo se gestionan las transacciones y qué funcionalidades están disponibles. Elegir el motor correcto es clave para el rendimiento y la integridad de la aplicación.

InnoDB

InnoDB es el motor predeterminado desde MySQL 5.5 y el más utilizado en entornos de producción. Ofrece soporte completo de transacciones ACID, claves foráneas y bloqueo a nivel de fila.

SQL
-- InnoDB se usa por defecto
CREATE TABLE clientes (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE
) ENGINE=InnoDB;

-- Soporta transacciones
START TRANSACTION;
UPDATE cuentas SET saldo = saldo - 500 WHERE id = 1;
UPDATE cuentas SET saldo = saldo + 500 WHERE id = 2;
COMMIT;

-- Soporta claves foráneas
CREATE TABLE pedidos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    cliente_id INT,
    total DECIMAL(10,2),
    FOREIGN KEY (cliente_id) REFERENCES clientes(id)
) ENGINE=InnoDB;

Características destacadas:

  • ACID: Atomicidad, Consistencia, Aislamiento y Durabilidad.
  • Row-level locking: Permite alta concurrencia en escrituras.
  • MVCC: Control de concurrencia multiversión para lecturas consistentes.
  • Clustering index: Los datos se almacenan en el propio índice primario.
  • Buffer Pool: Caché de datos e índices en memoria.

MyISAM

MyISAM fue el motor predeterminado antes de MySQL 5.5. Es más simple, rápido en lecturas secuenciales pero carece de transacciones y bloquea a nivel de tabla.

SQL
CREATE TABLE logs (
    id INT AUTO_INCREMENT PRIMARY KEY,
    accion VARCHAR(50),
    fecha TIMESTAMP
) ENGINE=MyISAM;

-- MyISAM soporta FULLTEXT sin dependencias adicionales
CREATE FULLTEXT INDEX ft_logs ON logs(accion);

-- Bloqueo a nivel de tabla: una escritura bloquea toda la tabla
INSERT INTO logs (accion) VALUES ('login'); -- Bloquea la tabla hasta completar

Memory

El motor Memory almacena todos los datos en RAM, lo que lo hace extremadamente rápido pero volátil: los datos se pierden al reiniciar el servidor.

SQL
CREATE TABLE sesiones (
    id VARCHAR(32) PRIMARY KEY,
    datos TEXT,
    ultima_actividad TIMESTAMP
) ENGINE=Memory;

-- Ideal para tablas temporales, cachés y sesiones
-- Los datos desaparecen al reiniciar MySQL

CSV y ARCHIVE

El motor CSV almacena datos en archivos de texto separados por comas, útil para intercambio de datos. ARCHIVE comprime los datos al insertar y solo permite lecturas con full scan, ideal para datos históricos.

SQL
CREATE TABLE datos_exportados (
    id INT,
    nombre VARCHAR(100),
    email VARCHAR(100)
) ENGINE=CSV;
-- Cada fila es una línea en el archivo .csv

CREATE TABLE historico_auditoria (
    id INT AUTO_INCREMENT PRIMARY KEY,
    accion TEXT,
    fecha TIMESTAMP
) ENGINE=ARCHIVE;
-- Solo soporta INSERT y SELECT (sin DELETE ni UPDATE)

Cómo elegir el motor

La elección depende del caso de uso:

  • InnoDB: Aplicaciones transaccionales, sistemas bancarios, e-commerce, cualquier entorno donde la integridad de los datos sea crítica.
  • MyISAM: Tablas de solo lectura, almacenes de datos analíticos, logs históricos donde no importe la integridad transaccional.
  • Memory: Tablas temporales, cachés, sesiones de usuario, datos que puedan reconstruirse fácilmente.
  • CSV: Exportación directa a hojas de cálculo, integración con herramientas externas que procesan CSV.
  • ARCHIVE: Auditoría, logs de larga retención, datos que se escriben una vez y se leen raramente.

InnoDB es el motor predeterminado y recomendado para la gran mayoría de aplicaciones. Solo considera otros motores cuando tengas necesidades muy específicas que InnoDB no cubra, como tablas en RAM (Memory) o datos de solo lectura masivos (MyISAM).

Ver el motor de una tabla

SQL
-- Ver motores disponibles
SHOW ENGINES;

-- Ver el motor de una tabla específica
SHOW TABLE STATUS WHERE Name = 'clientes';

-- Cambiar el motor de una tabla existente
ALTER TABLE clientes ENGINE=InnoDB;
