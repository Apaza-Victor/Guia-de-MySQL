Triggers en MySQL

Un trigger (desencadenador) es un bloque de código SQL que se ejecuta automáticamente en respuesta a un evento en una tabla: INSERT, UPDATE o DELETE. Los triggers son útiles para auditoría, validación de datos, sincronización entre tablas y aplicación de reglas de negocio a nivel de base de datos.

CREATE TRIGGER

La sintaxis para crear un trigger especifica el momento (BEFORE o AFTER), el evento (INSERT, UPDATE, DELETE), la tabla asociada y el cuerpo del trigger:

SQL
DELIMITER $$

CREATE TRIGGER before_empleado_insert
BEFORE INSERT ON empleados
FOR EACH ROW
BEGIN
    -- Asignar fecha de creación automática
    SET NEW.fecha_creacion = NOW();

    -- Validar salario mínimo
    IF NEW.salario < 1000 THEN
        SET NEW.salario = 1000;
    END IF;
END$$

DELIMITER ;

BEFORE vs AFTER y OLD vs NEW

Los triggers BEFORE se ejecutan antes de que la operación afecte la tabla; son ideales para validaciones y modificaciones previas. Los triggers AFTER se ejecutan después y son adecuados para auditoría y sincronización.

MySQL expone los valores de la fila afectada mediante los alias OLD (valor antes del cambio) y NEW (valor después del cambio):

EventoOLDNEW
INSERTNo existe (todos NULL)Valores insertados
UPDATEValores antes de la modificaciónValores después de la modificación
DELETEValores eliminadosNo existe (todos NULL)

Ejemplo: trigger de auditoría

Registramos cada cambio salarial en una tabla auditoria_salarios:

SQL
-- Tabla de auditoría
CREATE TABLE auditoria_salarios (
    id INT AUTO_INCREMENT PRIMARY KEY,
    empleado_id INT NOT NULL,
    salario_anterior DECIMAL(10,2),
    salario_nuevo DECIMAL(10,2),
    modificado_por VARCHAR(100),
    fecha_modificacion DATETIME DEFAULT NOW(),
    accion VARCHAR(20)
);

-- Trigger AFTER UPDATE
DELIMITER $$

CREATE TRIGGER after_empleado_update_salario
AFTER UPDATE ON empleados
FOR EACH ROW
BEGIN
    -- Solo registrar si el salario cambió
    IF OLD.salario != NEW.salario THEN
        INSERT INTO auditoria_salarios(
            empleado_id, salario_anterior, salario_nuevo,
            modificado_por, accion
        ) VALUES (
            NEW.id, OLD.salario, NEW.salario,
            USER(), 'UPDATE'
        );
    END IF;
END$$

DELIMITER ;
SQL
-- Trigger AFTER DELETE
DELIMITER $$

CREATE TRIGGER after_empleado_delete
AFTER DELETE ON empleados
FOR EACH ROW
BEGIN
    INSERT INTO auditoria_salarios(
        empleado_id, salario_anterior, salario_nuevo,
        modificado_por, accion
    ) VALUES (
        OLD.id, OLD.salario, NULL,
        USER(), 'DELETE'
    );
END$$

DELIMITER ;

Trigger BEFORE INSERT con validación

SQL
DELIMITER $$

CREATE TRIGGER before_pedido_insert
BEFORE INSERT ON pedidos
FOR EACH ROW
BEGIN
    DECLARE stock_actual INT;

    -- Verificar stock disponible
    SELECT stock INTO stock_actual
    FROM productos
    WHERE id = NEW.producto_id;

    IF stock_actual < NEW.cantidad THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Stock insuficiente para realizar el pedido';
    END IF;

    -- Calcular precio total
    SET NEW.total = NEW.cantidad * NEW.precio_unitario;
    SET NEW.fecha_pedido = NOW();
END$$

DELIMITER ;

Ver y eliminar triggers

SQL
-- Ver triggers de la base de datos
SHOW TRIGGERS;

-- Ver definición de un trigger específico
SHOW CREATE TRIGGER after_empleado_update_salario;

-- Eliminar un trigger
DROP TRIGGER IF EXISTS after_empleado_update_salario;
TriggerEventoTablaTiming
before_empleado_insertINSERTempleadosBEFORE
after_empleado_update_salarioUPDATEempleadosAFTER
after_empleado_deleteDELETEempleadosAFTER
before_pedido_insertINSERTpedidosBEFORE

Usa SIGNAL SQLSTATE '45000' para lanzar errores personalizados dentro de un trigger. Esto permite rechazar operaciones que no cumplan las reglas de negocio, como saldos negativos o stock insuficiente.

Abusar de los triggers puede hacer que la depuración sea muy difícil. Como los triggers se ejecutan de forma invisible para la aplicación, un error dentro de un trigger puede hacer fallar una operación sin que el desarrollador lo anticipé. Además, los triggers pueden generar efectos en cascada (un trigger que modifica otra tabla donde hay otro trigger). Usa triggers con moderación y documenta cada uno claramente.
