Eventos programados

El Event Scheduler de MySQL permite ejecutar tareas SQL automáticamente en intervalos programados, similar a cron en Linux o el Task Scheduler de Windows. Los eventos son ideales para tareas de mantenimiento como limpieza de logs, generación de reportes periódicos, actualización de estadísticas y archivado de datos antiguos.

Verificar el Event Scheduler

El Event Scheduler puede estar activado o desactivado. Para verificarlo y activarlo si es necesario:

SQL
-- Verificar estado del Event Scheduler
SHOW VARIABLES LIKE 'event_scheduler';

-- Activar el Event Scheduler (en sesión actual)
SET GLOBAL event_scheduler = ON;

-- Para activarlo permanentemente, añadir en my.cnf / my.ini:
-- event_scheduler = ON

CREATE EVENT

La sintaxis para crear un evento incluye el nombre, la programación con ON SCHEDULE, opcionalmente STARTS y ENDS, y el cuerpo con las sentencias SQL:

SQL
-- Evento único que se ejecuta una vez en una fecha específica
CREATE EVENT evento_unico
ON SCHEDULE AT '2025-12-31 23:59:59'
DO
    UPDATE campañas SET activa = 0 WHERE YEAR(fecha_fin) = 2025;

-- Evento recurrente cada día a medianoche
CREATE EVENT limpiar_sesiones
ON SCHEDULE EVERY 1 DAY
STARTS '2025-01-01 00:00:00'
DO
    DELETE FROM sesiones WHERE fecha_expiracion < NOW();

Programación avanzada con EVERY, STARTS y ENDS

SQL
-- Cada hora, durante un año
CREATE EVENT evento_horario
ON SCHEDULE EVERY 1 HOUR
STARTS '2025-01-01 00:00:00'
ENDS '2025-12-31 23:59:59'
DO
    INSERT INTO logs_ejecucion(descripcion) VALUES('Ejecución horaria');

-- Cada 15 minutos, sin fecha de fin
CREATE EVENT cada_15_minutos
ON SCHEDULE EVERY 15 MINUTE
DO
    CALL actualizar_estadisticas();

-- El primer día de cada mes a las 2 AM
CREATE EVENT reporte_mensual
ON SCHEDULE EVERY 1 MONTH
STARTS '2025-01-01 02:00:00'
DO
    CALL generar_reporte_mensual();

Ejemplo: limpiar logs viejos cada semana

Un caso de uso típico es eliminar registros de logs que superen cierta antigüedad para evitar que la tabla crezca indefinidamente:

SQL
-- Tabla de logs
CREATE TABLE logs_aplicacion (
    id INT AUTO_INCREMENT PRIMARY KEY,
    mensaje TEXT,
    nivel ENUM('INFO', 'WARNING', 'ERROR'),
    fecha_creacion DATETIME DEFAULT NOW(),
    INDEX idx_fecha (fecha_creacion)
);

-- Evento que elimina logs mayores a 90 días cada semana
DELIMITER $$

CREATE EVENT limpiar_logs_semanal
ON SCHEDULE EVERY 1 WEEK
STARTS '2025-01-06 03:00:00'  -- Lunes 3:00 AM
DO
BEGIN
    DELETE FROM logs_aplicacion
    WHERE fecha_creacion < DATE_SUB(NOW(), INTERVAL 90 DAY);

    -- Registrar la limpieza en una tabla de control
    INSERT INTO control_eventos(evento, ejecutado_en, filas_afectadas)
    VALUES('limpiar_logs_semanal', NOW(), ROW_COUNT());
END$$

DELIMITER ;

Gestión de eventos

SQL
-- Ver todos los eventos
SHOW EVENTS;

-- Ver eventos de una base de datos específica
SHOW EVENTS FROM mi_base_datos;

-- Ver definición de un evento
SHOW CREATE EVENT limpiar_logs_semanal;

-- Deshabilitar un evento (sin eliminarlo)
ALTER EVENT limpiar_logs_semanal DISABLE;

-- Habilitar un evento deshabilitado
ALTER EVENT limpiar_logs_semanal ENABLE;

-- Modificar la programación de un evento
ALTER EVENT limpiar_logs_semanal
ON SCHEDULE EVERY 2 WEEK;

-- Eliminar un evento
DROP EVENT IF EXISTS limpiar_logs_semanal;

Los eventos se almacenan en la base de datos mysql y persisten tras reinicios del servidor (a diferencia del scheduler del sistema operativo). Son una excelente alternativa a cron cuando no tienes acceso al sistema operativo del servidor de base de datos. Recuerda verificar que el Event Scheduler esté activo, especialmente después de reiniciar MySQL.

Los eventos se ejecutan en el hilo del scheduler. Si un evento tarda más tiempo del intervalo programado, pueden solaparse ejecuciones. Considera usar IF NOT EXISTS o una tabla de control para evitar ejecuciones concurrentes. Además, los eventos no se replican por defecto en configuraciones de replicación a menos que se configuren explícitamente.
