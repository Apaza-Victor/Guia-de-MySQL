Índices en MySQL

Los índices son estructuras auxiliares que aceleran la búsqueda de filas en una tabla. Funcionan de forma análoga al índice de un libro: en lugar de leer página por página, consultas directamente la ubicación de los datos. Sin índices, MySQL debe recorrer toda la tabla (full table scan) para encontrar los registros solicitados.

Qué son los índices

Un índice es una copia parcial de los datos organizada de forma eficiente para búsquedas rápidas. Se implementa típicamente como un árbol B+ (B-tree) o una tabla hash, y almacena pares clave + puntero a la fila real. Cuando ejecutas una consulta con WHERE, JOIN u ORDER BY, el optimizador de MySQL decide si usar un índice disponible.

CREATE INDEX

La sintaxis básica para crear un índice es:

SQL
-- Índice simple sobre una columna
CREATE INDEX idx_apellido ON empleados(apellido);

-- Índice compuesto sobre varias columnas
CREATE INDEX idx_nombre_completo ON empleados(nombre, apellido);

-- Índice único (no permite duplicados)
CREATE UNIQUE INDEX idx_email ON usuarios(email);

-- Índice FULLTEXT para búsqueda textual
CREATE FULLTEXT INDEX idx_contenido ON articulos(contenido);

-- Eliminar un índice
DROP INDEX idx_apellido ON empleados;

Tipos de índices en MySQL

MySQL soporta varios tipos de índices según el motor de almacenamiento. InnoDB (el motor por defecto) utiliza B-tree para la mayoría de los índices.

TipoMotor compatibleUso principal
B-treeInnoDB, MyISAM, MemoryÍndice por defecto. Ideal para =, >, <, BETWEEN, LIKE sin comodín inicial, ORDER BY
HashMemory, NDBBúsquedas exactas con =. No soporta rangos ni ORDER BY
FULLTEXTInnoDB, MyISAMBúsqueda de texto completo con MATCH ... AGAINST
Spatial (R-tree)InnoDB, MyISAMDatos geográficos y geométricos

Índices simples y compuestos

Un índice simple se crea sobre una sola columna. Un índice compuesto abarca dos o más columnas y respeta la regla del prefijo más a la izquierda (leftmost prefix): para que el índice se use, las condiciones deben empezar por la primera columna del índice.

SQL
-- Índice compuesto: (ciudad, departamento, salario)
CREATE INDEX idx_ubicacion ON empleados(ciudad, departamento, salario);

-- Usa el índice (primeras columnas presentes)
SELECT * FROM empleados WHERE ciudad = 'Bogotá';
SELECT * FROM empleados WHERE ciudad = 'Bogotá' AND departamento = 'Ventas';

-- NO usa el índice (falta la primera columna)
SELECT * FROM empleados WHERE departamento = 'Ventas';

Ejemplo práctico: consulta con y sin índice

Supongamos una tabla usuarios con 10 000 registros. Buscamos un usuario por su correo electrónico. Sin índice, MySQL examina fila por fila; con índice, localiza el registro al instante.

SQL
-- Crear tabla de prueba
CREATE TABLE usuarios (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(50),
    email VARCHAR(100)
);

-- Insertar 10 000 registros (omitido por brevedad)

-- 1. Consulta SIN índice
EXPLAIN SELECT * FROM usuarios WHERE email = 'usuario5000@email.com';
-- type: ALL (full table scan), rows: 10000

-- 2. Crear índice
CREATE INDEX idx_email ON usuarios(email);

-- 3. Consulta CON índice
EXPLAIN SELECT * FROM usuarios WHERE email = 'usuario5000@email.com';
-- type: ref, rows: 1, Extra: Using index condition

Usa EXPLAIN antes de cada consulta lenta para verificar si el índice se está utilizando. La columna type indica la calidad del acceso: const > ref > range > index > ALL.

No indexes todas las columnas. Cada índice adicional ralentiza las operaciones INSERT, UPDATE y DELETE porque el índice debe actualizarse simultáneamente. Indexa solo las columnas que aparecen frecuentemente en WHERE, JOIN y ORDER BY.

Cuándo usar índices

Crea índices cuando:

  • Columnas usadas en cláusulas WHERE con alta selectividad (muchos valores distintos).
  • Columnas involucradas en JOIN (claves foráneas).
  • Columnas usadas en ORDER BY para evitar filesorts.
  • Columnas con restricción UNIQUE.

Cuándo evitarlos

Evita índices cuando:

  • La tabla es muy pequeña (menos de 100 filas) — un full scan es más rápido.
  • La columna tiene baja selectividad (ej: sexo con solo 'M' y 'F').
  • La tabla recibe muchas escrituras y pocas lecturas.
  • La columna se modifica con frecuencia.
