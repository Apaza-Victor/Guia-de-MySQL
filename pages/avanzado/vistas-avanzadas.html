Vistas avanzadas

Las vistas son consultas almacenadas que se comportan como tablas virtuales. Más allá de las vistas básicas, MySQL ofrece funcionalidades avanzadas como vistas actualizables, la cláusula WITH CHECK OPTION y técnicas para simular vistas materializadas.

Vistas actualizables

No todas las vistas permiten operaciones INSERT, UPDATE o DELETE. Una vista es actualizable si cumple ciertas condiciones: no usa funciones de agregación (SUM, COUNT, etc.), no usa DISTINCT, GROUP BY, HAVING, UNION, ni subconsultas en la cláusula SELECT. Cuando una vista es actualizable, los cambios se reflejan directamente en la tabla subyacente.

SQL
-- Vista actualizable: empleados activos
CREATE VIEW empleados_activos AS
SELECT id, nombre, apellido, email, salario, depto_id
FROM empleados
WHERE activo = 1;

-- INSERT a través de la vista
INSERT INTO empleados_activos(nombre, apellido, email, salario, depto_id)
VALUES('Pedro', 'Ramírez', 'pedro@email.com', 3500, 2);

-- Esto inserta en la tabla 'empleados' con activo = 1 (si tiene valor por defecto)
-- o con activo = NULL si está definida como NULL por defecto

-- UPDATE a través de la vista
UPDATE empleados_activos
SET salario = 3800
WHERE id = 10;

-- DELETE a través de la vista
DELETE FROM empleados_activos WHERE id = 15;

WITH CHECK OPTION

WITH CHECK OPTION evita que se inserten o modifiquen filas que no cumplan la condición WHERE de la vista. Esto garantiza que todas las operaciones a través de la vista mantengan la coherencia del subconjunto que la vista representa:

SQL
-- Vista con WITH CHECK OPTION
CREATE VIEW empleados_salario_alto AS
SELECT id, nombre, apellido, salario
FROM empleados
WHERE salario >= 5000
WITH CHECK OPTION;

-- Esto funciona (salario >= 5000)
INSERT INTO empleados_salario_alto(nombre, apellido, salario)
VALUES('Laura', 'Gómez', 5500);

-- Esto FALLA con error: CHECK OPTION failed
INSERT INTO empleados_salario_alto(nombre, apellido, salario)
VALUES('Tomás', 'Pérez', 3000);

-- También evita UPDATE que saque la fila de la vista
UPDATE empleados_salario_alto
SET salario = 4000
WHERE id = 20;
-- Error: CHECK OPTION failed 'db.empleados_salario_alto'

Limitaciones de las vistas en MySQL

  • No se pueden crear índices directamente sobre una vista. La vista usa los índices de las tablas subyacentes.
  • Las vistas con GROUP BY o funciones de agregación no son actualizables.
  • El rendimiento de una vista compleja puede ser pobre porque MySQL ejecuta la consulta subyacente cada vez que se accede a la vista (no hay almacenamiento en caché).
  • No se pueden usar tablas temporales en la definición de una vista.
  • Las vistas pueden ocultar índices útiles, haciendo que el optimizador elija planes subóptimos.

Simular vistas materializadas

MySQL no soporta vistas materializadas nativamente (como Oracle o PostgreSQL). Sin embargo, se pueden simular combinando una tabla física que almacene los datos precalculados y un evento que la actualice periódicamente. Esto es útil para reportes pesados que no requieren datos en tiempo real:

SQL
-- 1. Crear tabla física para la "vista materializada"
CREATE TABLE resumen_ventas_mensual AS
SELECT DATE_FORMAT(fecha, '%Y-%m') AS mes,
       COUNT(*) AS total_pedidos,
       SUM(total) AS ingresos_totales,
       AVG(total) AS ticket_promedio
FROM pedidos
GROUP BY mes
WITH NO DATA;

-- 2. Crear procedimiento para refrescar los datos
DELIMITER $$

CREATE PROCEDURE refrescar_resumen_ventas()
BEGIN
    TRUNCATE TABLE resumen_ventas_mensual;

    INSERT INTO resumen_ventas_mensual (mes, total_pedidos, ingresos_totales, ticket_promedio)
    SELECT DATE_FORMAT(fecha, '%Y-%m') AS mes,
           COUNT(*) AS total_pedidos,
           SUM(total) AS ingresos_totales,
           AVG(total) AS ticket_promedio
    FROM pedidos
    GROUP BY mes;
END$$

DELIMITER ;

-- 3. Evento para refrescar cada noche a las 2 AM
CREATE EVENT refrescar_resumen_ventas
ON SCHEDULE EVERY 1 DAY
STARTS '2025-01-01 02:00:00'
DO
    CALL refrescar_resumen_ventas();

Para reportes en tiempo real, usa vistas regulares (los datos siempre están actualizados). Para reportes pesados o históricos, la técnica de tabla física + evento es más eficiente porque evita recalcular datos cada vez que se consulta. También puedes refrescar la tabla manualmente con CALL refrescar_resumen_ventas() después de una carga importante de datos.

Las tablas que simulan vistas materializadas contienen datos redundantes. Debes considerar el espacio de almacenamiento adicional y la posible desincronización entre los datos originales y la copia. Diseña la frecuencia de actualización según la tolerancia a la desactualización del negocio.
