Transacciones en MySQL

Una transacción es una unidad lógica de trabajo compuesta por una o más operaciones SQL que se ejecutan como un bloque atómico. Si alguna operación falla, toda la transacción se deshace (rollback) para mantener la consistencia de los datos. Las transacciones son fundamentales para garantizar la integridad en sistemas bancarios, pedidos, inventarios y cualquier escenario donde los datos deban permanecer en un estado coherente.

START TRANSACTION, COMMIT y ROLLBACK

MySQL trabaja en modo autocommit por defecto (cada sentencia es una transacción implícita). Para agrupar varias operaciones, iniciamos una transacción explícita:

SQL
-- Iniciar transacción
START TRANSACTION;

-- Descontar $500 de la cuenta A
UPDATE cuentas SET saldo = saldo - 500 WHERE id = 1;

-- Acreditar $500 a la cuenta B
UPDATE cuentas SET saldo = saldo + 500 WHERE id = 2;

-- Si todo va bien, confirmar cambios
COMMIT;

-- Si algo falla, deshacer cambios
ROLLBACK;

Propiedades ACID

Las transacciones en InnoDB garantizan las cuatro propiedades ACID:

PropiedadSignificadoCómo lo garantiza MySQL
AtomicityLa transacción se ejecuta completamente o no se ejecutaRedo / Undo logs en InnoDB
ConsistencyLos datos siempre cumplen las reglas de integridadRestricciones, claves foráneas, triggers
IsolationLas transacciones concurrentes no se interfierenNiveles de aislamiento (READ COMMITTED, etc.)
DurabilityLos datos confirmados persisten ante fallosBuffer pool + write-ahead logging

SAVEPOINT y ROLLBACK TO SAVEPOINT

Los savepoints permiten establecer puntos intermedios dentro de una transacción para deshacer solo una parte de ella sin abortar completamente:

SQL
START TRANSACTION;

INSERT INTO logs(accion) VALUES('Paso 1');
SAVEPOINT paso1;

INSERT INTO logs(accion) VALUES('Paso 2');
SAVEPOINT paso2;

INSERT INTO logs(accion) VALUES('Paso 3 (fallará)');

-- Deshacer solo hasta paso2
ROLLBACK TO SAVEPOINT paso2;

-- Confirmar (solo quedan Paso 1 y Paso 2)
COMMIT;

Ejemplo completo: transferencia bancaria

Imagina una transferencia de $200 entre dos cuentas. Si falla el crédito después del débito, el dinero no debe perderse:

SQL
START TRANSACTION;

-- 1. Verificar saldo disponible
SELECT saldo FROM cuentas WHERE id = 1 FOR UPDATE;
-- Resultado: 1000

-- 2. Débito de la cuenta origen (id = 1)
UPDATE cuentas SET saldo = saldo - 200 WHERE id = 1;
-- Si el saldo se vuelve negativo, la app debe hacer ROLLBACK

-- 3. Crédito a la cuenta destino (id = 2)
UPDATE cuentas SET saldo = saldo + 200 WHERE id = 2;

-- 4. Registrar en auditoría
INSERT INTO transferencias(cuenta_origen, cuenta_destino, monto, fecha)
VALUES(1, 2, 200, NOW());

-- 5. Confirmar
COMMIT;
MomentoCuenta 1 (origen)Cuenta 2 (destino)
Antes de la transferencia$1000.00$500.00
Después del débito (aún sin COMMIT)$800.00$500.00
Después del crédito + COMMIT$800.00$700.00
Si ocurre ROLLBACK$1000.00$500.00

Errores típicos con transacciones: olvidar el COMMIT dejando la transacción abierta (bloquea filas con locks), no manejar excepciones en la aplicación provocando que el ROLLBACK nunca se ejecute, y mezclar motores de almacenamiento (MyISAM no soporta transacciones, lo que causa un commit implícito).

Usa SET autocommit = 0 para deshabilitar el autocommit globalmente en una sesión. Revisa las transacciones activas con SELECT * FROM information_schema.INNODB_TRX\G.
