Vistas (VIEW)

Una vista es una tabla virtual cuyo contenido está definido por una consulta SELECT almacenada. Las vistas no almacenan datos físicamente (excepto las vistas materializadas, que MySQL no soporta nativamente), sino que muestran datos de las tablas subyacentes cada vez que se consultan. Son ideales para simplificar consultas complejas y mejorar la seguridad.

Crear una vista con CREATE VIEW

La sintaxis básica para crear una vista es CREATE VIEW nombre_vista AS consulta_select.

SQL
-- Vista de resumen de clientes con sus pedidos
CREATE VIEW resumen_clientes AS
SELECT
  c.id,
  c.nombre,
  c.ciudad,
  COUNT(p.id) AS total_pedidos,
  COALESCE(SUM(p.total), 0) AS gasto_total,
  COALESCE(ROUND(AVG(p.total), 2), 0) AS ticket_promedio
FROM clientes c
LEFT JOIN pedidos p ON c.id = p.cliente_id
GROUP BY c.id, c.nombre, c.ciudad;

Consultar una vista

Una vez creada, la vista se usa como cualquier tabla en una consulta SELECT. Puedes aplicar WHERE, ORDER BY, GROUP BY y hasta hacer JOIN con otras tablas o vistas.

SQL
-- Consultar la vista directamente
SELECT * FROM resumen_clientes;

-- Filtrar sobre la vista
SELECT * FROM resumen_clientes
WHERE gasto_total > 0
ORDER BY gasto_total DESC;

Modificar una vista con ALTER VIEW

Para cambiar la definición de una vista existente sin eliminarla, usa ALTER VIEW. También puedes usar CREATE OR REPLACE VIEW, que crea la vista si no existe o la reemplaza si ya existe.

SQL
-- Añadir la fecha del último pedido a la vista
CREATE OR REPLACE VIEW resumen_clientes AS
SELECT
  c.id,
  c.nombre,
  c.ciudad,
  COUNT(p.id) AS total_pedidos,
  COALESCE(SUM(p.total), 0) AS gasto_total,
  MAX(p.fecha) AS ultimo_pedido
FROM clientes c
LEFT JOIN pedidos p ON c.id = p.cliente_id
GROUP BY c.id, c.nombre, c.ciudad;

Eliminar una vista con DROP VIEW

Para eliminar una vista de la base de datos, usa DROP VIEW. Puedes eliminar varias vistas en una sola sentencia separándolas con comas.

SQL
DROP VIEW IF EXISTS resumen_clientes;
-- DROP VIEW IF EXISTS vista1, vista2, vista3;

WITH CHECK OPTION

Cuando creas una vista actualizable (que permite INSERT, UPDATE, DELETE), WITH CHECK OPTION evita que se realicen cambios que hagan que la fila desaparezca de la vista. Es una capa adicional de integridad.

SQL
-- Vista de solo clientes de Madrid con protección
CREATE VIEW clientes_madrid AS
SELECT id, nombre, ciudad
FROM clientes
WHERE ciudad = 'Madrid'
WITH CHECK OPTION;

-- Esto funcionará
UPDATE clientes_madrid SET nombre = 'Ana García' WHERE id = 1;

-- Esto fallará por WITH CHECK OPTION
UPDATE clientes_madrid SET ciudad = 'Barcelona' WHERE id = 1;

Ventajas de las vistas

Las vistas ofrecen tres beneficios principales: seguridad al ocultar columnas sensibles, simplicidad al encapsular consultas complejas y consistencia al proporcionar una interfaz estable aunque cambien las tablas subyacentes. También facilitan el mantenimiento del código en aplicaciones.

SQL
-- Vista que oculta datos sensibles
CREATE VIEW clientes_publico AS
SELECT id, nombre, ciudad
FROM clientes;
-- La columna 'telefono' o 'email' no se expone

-- Vista que simplifica un reporte mensual
CREATE VIEW reporte_mensual AS
SELECT
  DATE_FORMAT(fecha, '%Y-%m') AS mes,
  COUNT(*) AS pedidos,
  SUM(total) AS ingresos,
  ROUND(AVG(total), 2) AS ticket_medio
FROM pedidos
GROUP BY DATE_FORMAT(fecha, '%Y-%m')
ORDER BY mes;

¿Cuándo usar vistas? Úsalas cuando una consulta se repite en múltiples reportes o aplicaciones, cuando necesitas restringir el acceso a columnas sensibles sin crear tablas adicionales, o para crear una capa de abstracción entre el esquema físico y las aplicaciones. Evita crear vistas que consulten otras vistas en cadena, ya que puede degradar el rendimiento.
