Seguridad en MySQL

La seguridad de las bases de datos es un aspecto crítico en cualquier aplicación. MySQL ofrece múltiples mecanismos para proteger los datos contra accesos no autorizados, ataques de inyección SQL y fugas de información sensible.

Inyección SQL

La inyección SQL es una técnica de ataque en la que el intruso inserta código SQL malicioso a través de campos de entrada del usuario. Si la aplicación no sanitiza correctamente las entradas, el atacante puede leer, modificar o eliminar datos arbitrarios.

SQL
-- Ejemplo VULNERABLE: concatenación directa de variables
SELECT * FROM usuarios WHERE email = '$email' AND password = '$password';

-- Si el atacante ingresa: ' OR '1'='1
-- La consulta se convierte en:
SELECT * FROM usuarios WHERE email = '' OR '1'='1' AND password = '' OR '1'='1';
-- Esto devuelve todos los usuarios, evadiendo la autenticación.

Prevención con prepared statements

La forma más efectiva de prevenir la inyección SQL es usar prepared statements (consultas parametrizadas). Estas separan el código SQL de los datos, impidiendo que los valores ingresados sean interpretados como parte de la sentencia.

SQL
-- Ejemplo SEGURO con prepared statements en SQL nativo
PREPARE stmt FROM 'SELECT * FROM usuarios WHERE email = ? AND password = ?';
SET @email = 'usuario@ejemplo.com';
SET @password = 'clave_segura';
EXECUTE stmt USING @email, @password;
DEALLOCATE PREPARE stmt;
PHP (PDO)
$stmt = $pdo->prepare("SELECT * FROM usuarios WHERE email = ? AND password = ?");
$stmt->execute([$email, $password]);
Python (mysql-connector)
cursor.execute("SELECT * FROM usuarios WHERE email = %s AND password = %s", (email, password))

Cifrado de datos

MySQL proporciona funciones de cifrado para proteger datos sensibles tanto en tránsito como en reposo. Para conexiones se utiliza SSL/TLS, y para datos almacenados se dispone de AES_ENCRYPT y AES_DECRYPT.

SQL
-- Cifrar un dato con AES-256
INSERT INTO tarjetas (numero_cifrado) VALUES (AES_ENCRYPT('4111111111111111', 'clave_secreta'));

-- Descifrar el dato
SELECT AES_DECRYPT(numero_cifrado, 'clave_secreta') FROM tarjetas;

Buenas prácticas de configuración

Ajustar correctamente la configuración del servidor MySQL reduce significativamente la superficie de ataque. Las siguientes recomendaciones deberían aplicarse en todo entorno de producción:

bash
# Vincular solo a la interfaz local
bind-address = 127.0.0.1

# Cambiar el puerto por defecto (opcional)
port = 3307

# Deshabilitar el acceso remoto del usuario root
# (renombrar o eliminar root@'%')

# Activar logs de consultas lentas y errores
log_error = /var/log/mysql/error.log
slow_query_log = 1
long_query_time = 2

mysql_secure_installation

MySQL incluye un script interactivo llamado mysql_secure_installation que aplica una serie de medidas de seguridad básicas. Se recomienda ejecutarlo inmediatamente después de instalar MySQL.

bash
sudo mysql_secure_installation

El script guía al administrador a través de los siguientes pasos:

  • Establecer una contraseña para el usuario root.
  • Eliminar usuarios anónimos.
  • Deshabilitar el inicio de sesión remoto para root.
  • Eliminar la base de datos de prueba test.
  • Recargar las tablas de privilegios.

Las prepared statements son la defensa más eficaz contra la inyección SQL. Nunca concatenes valores directamente en las consultas SQL. Combínalas con la validación de entrada y el principio de mínimo privilegio para una defensa en profundidad.
