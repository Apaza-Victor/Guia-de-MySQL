Backup y restauración

Realizar copias de seguridad periódicas es una de las tareas más importantes para cualquier administrador de bases de datos. MySQL incluye la herramienta mysqldump, que genera archivos SQL con la estructura y los datos de una o varias bases de datos.

Tipos de backup con mysqldump

Existen distintos enfoques para realizar backups según la necesidad: respaldo completo, solo estructura, solo datos o bases específicas. La siguiente tabla compara cada tipo:

TipoComandoUso recomendado
Base de datos completamysqldump -u root -p bd > bd.sqlRespaldo diario de una base
Todas las basesmysqldump -u root -p --all-databases > todo.sqlRespaldo completo del servidor
Solo estructuramysqldump -u root -p --no-data bd > estructura.sqlVersionado de esquemas
Solo datosmysqldump -u root -p --no-create-info bd > datos.sqlMigración de datos entre servidores
Varias basesmysqldump -u root -p --databases bd1 bd2 > varias.sqlRespaldo selectivo de múltiples bases

Backup con rutinas y disparadores

Por defecto mysqldump incluye los procedimientos almacenados, funciones y eventos, pero es recomendable usar las opciones explícitas para asegurarse de que no se omitan.

bash
# Incluir rutinas y disparadores explícitamente
mysqldump -u root -p --routines --triggers --events mi_bd > mi_bd_completo.sql

# Comprimir el backup en el momento
mysqldump -u root -p mi_bd | gzip > mi_bd_$(date +%F).sql.gz

Restauración de una base de datos

Para restaurar un backup generado con mysqldump se utiliza el cliente mysql redirigiendo el archivo SQL como entrada. Es importante que la base de datos destino exista antes de restaurar.

bash
# Restaurar una base de datos
mysql -u root -p mi_bd < mi_bd_completo.sql

# Restaurar un backup comprimido
gunzip < mi_bd_2025-01-01.sql.gz | mysql -u root -p mi_bd

# Restaurar un backup completo del servidor
mysql -u root -p < todo.sql

Automación con cron

En entornos Linux, las tareas de backup se pueden automatizar mediante cron. El siguiente script programa un backup diario a las 2:00 AM con compresión y rotación de archivos.

bash
# Editar crontab: crontab -e
# Ejecutar backup cada día a las 2:00 AM
0 2 * * * /usr/bin/mysqldump -u root -p'password' --all-databases --routines --triggers | gzip > /backups/mysql_$(date +\%Y\%m\%d).sql.gz

# Eliminar backups de más de 30 días
0 3 * * * find /backups -name "mysql_*.sql.gz" -mtime +30 -delete

Establece una política de backups con frecuencia definida según la criticidad de los datos. Para bases de producción se recomienda un backup completo diario y backups diferenciales cada pocas horas. Verifica periódicamente que los archivos de respaldo se puedan restaurar correctamente.
