Ejercicios avanzados de SQL

Lleva tus habilidades al siguiente nivel con ejercicios de procedimientos almacenados, triggers, índices y optimización. Estos temas son esenciales para administrar bases de datos en entornos profesionales y de alto rendimiento.

Usa la sentencia EXPLAIN antes y después de crear índices para observar cómo MySQL optimiza las consultas. Esta práctica es fundamental para entender el rendimiento de las bases de datos.

Ejercicio 1: Procedimiento almacenado

Crea un procedimiento almacenado llamado ListarEmpleadosPorDepartamento que reciba un nombre de departamento como parámetro y devuelva el id, nombre, apellido, puesto y salario de los empleados en ese departamento. Luego ejecútalo para listar los empleados de Ventas.

Ver solución
SQL
DELIMITER //

CREATE PROCEDURE ListarEmpleadosPorDepartamento(IN dept VARCHAR(30))
BEGIN
  SELECT id, nombre, apellido, puesto, salario
  FROM empleados
  WHERE departamento = dept
  ORDER BY salario DESC;
END //

DELIMITER ;

Ejercicio 2: Trigger de auditoría

Crea un trigger after_insert_empleados que se active después de cada INSERT en la tabla empleados. Debe insertar un registro en la tabla audit_empleados con el ID del empleado, la acción 'INSERT', la fecha actual y el usuario actual (CURRENT_USER()). Luego prueba insertando un empleado nuevo y verifica la auditoría.

Ver solución
SQL
CREATE TRIGGER after_insert_empleados
AFTER INSERT ON empleados
FOR EACH ROW
BEGIN
  INSERT INTO audit_empleados (empleado_id, accion, fecha, usuario)
  VALUES (NEW.id, 'INSERT', NOW(), CURRENT_USER());
END;

-- Probar el trigger

Ejercicio 3: Índice compuesto y EXPLAIN

Ejecuta una consulta que busque empleados por departamento y ordenados por salario DESC. Primero usa EXPLAIN para ver el plan de ejecución sin índice. Luego crea un índice compuesto en (departamento, salario) y vuelve a ejecutar EXPLAIN para comparar.

Ver solución
SQL - Antes del índice
EXPLAIN SELECT * FROM empleados
WHERE departamento = 'TI'
ORDER BY salario DESC;

1SIMPLEempleadosALLNULLNULL11Using where; Using filesort
SQL - Crear índice
CREATE INDEX idx_dept_salario ON empleados(departamento, salario DESC);

EXPLAIN SELECT * FROM empleados
WHERE departamento = 'TI'
ORDER BY salario DESC;
idselect_typetabletypepossible_keyskeyrowsExtra
1SIMPLEempleadosrefidx_dept_salarioidx_dept_salario4Using index condition

Observa la diferencia: antes del índice el tipo era ALL (escaneo completo) y usaba filesort. Después del índice, el tipo pasa a ref y elimina el filesort, reduciendo las filas examinadas.

Ejercicio 4: Consulta optimizada vs versión lenta

Escribe una consulta lenta que use LIKE con comodín al inicio para buscar empleados cuyo nombre termine en 'a', y su versión optimizada usando una función de MySQL o reescribiendo la condición. Compara los planes de ejecución con EXPLAIN.

Ver solución
SQL - Versión lenta
-- Versión lenta: LIKE con comodín inicial (no puede usar índices)
EXPLAIN SELECT * FROM empleados
WHERE nombre LIKE '%a';
idselect_typetabletypepossible_keyskeyrowsExtra
1SIMPLEempleadosALLNULLNULL11Using where
SQL - Versión optimizada
-- Versión optimizada: usamos RIGHT() o indexamos con LIKE sin comodín inicial
CREATE INDEX idx_nombre ON empleados(nombre);

EXPLAIN SELECT * FROM empleados
WHERE RIGHT(nombre, 1) = 'a';

-- Alternativa aún mejor si el patrón lo permite: LIKE 'a%' (comodín al final)
EXPLAIN SELECT * FROM empleados
WHERE nombre LIKE 'a%';
idselect_typetabletypepossible_keyskeyrowsExtra
1SIMPLEempleadosALLNULLNULL11Using where

La versión con LIKE '%a' no puede usar índices porque el comodín está al inicio. La versión optimizada con LIKE 'a%' sí aprovecha el índice. En el caso de RIGHT(), MySQL igual hace escaneo completo porque la función envuelve la columna.

Conclusión: Para búsquedas eficientes por texto, evita los comodines al inicio del patrón o considera usar FULLTEXT INDEX con MATCH ... AGAINST.

Los índices aceleran las consultas de lectura pero ralentizan las escrituras (INSERT, UPDATE, DELETE). Evalúa siempre el equilibrio entre rendimiento de lectura y escritura antes de crear índices. Usa EXPLAIN como tu herramienta principal de diagnóstico.
