Proyectos prácticos guiados

Estos proyectos integradores te permitirán aplicar todo lo aprendido en situaciones reales. Cada proyecto incluye el esquema completo de la base de datos, los scripts de creación, datos de ejemplo y un conjunto de consultas para resolver. Se recomienda empezar por el Proyecto 1 e ir avanzando progresivamente.

Crea una base de datos independiente para cada proyecto. Así podrás experimentar sin afectar otros ejercicios y practicar también la administración de bases de datos.

Proyecto 1: Sistema de Tienda Online

Un sistema básico de tienda con productos categorizados, clientes que realizan pedidos con múltiples líneas de detalle. Este proyecto cubre relaciones de uno a muchos y muchos a muchos.

Diagrama textual

categorías (1) ──── (N) productos (N) ──── (N) detalle_pedidos (N) ──── (1) pedidos (N) ──── (1) clientes
SQL - Creación del esquema
CREATE TABLE categorias (
  id INT PRIMARY KEY AUTO_INCREMENT,
  nombre VARCHAR(50) NOT NULL,
  descripcion TEXT
);

CREATE TABLE productos (
  id INT PRIMARY KEY AUTO_INCREMENT,
  nombre VARCHAR(100) NOT NULL,
  precio DECIMAL(10,2) NOT NULL,
  stock INT DEFAULT 0,
  categoria_id INT,
  FOREIGN KEY (categoria_id) REFERENCES categorias(id)
);

CREATE TABLE clientes (
  id INT PRIMARY KEY AUTO_INCREMENT,
  nombre VARCHAR(80) NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  telefono VARCHAR(20),
  ciudad VARCHAR(50)
);

CREATE TABLE pedidos (
  id INT PRIMARY KEY AUTO_INCREMENT,
  cliente_id INT NOT NULL,
  fecha DATE NOT NULL,
  total DECIMAL(10,2) DEFAULT 0,
  FOREIGN KEY (cliente_id) REFERENCES clientes(id)
);

CREATE TABLE detalle_pedidos (
  id INT PRIMARY KEY AUTO_INCREMENT,
  pedido_id INT NOT NULL,
  producto_id INT NOT NULL,
  cantidad INT NOT NULL,
  precio_unitario DECIMAL(10,2) NOT NULL,
  FOREIGN KEY (pedido_id) REFERENCES pedidos(id),
  FOREIGN KEY (producto_id) REFERENCES productos(id)
);

Consultas para resolver

1. Obtén el nombre del cliente, la fecha del pedido y el total de cada pedido, ordenado por fecha descendente.

SELECT c.nombre, p.fecha, p.total
FROM clientes c
INNER JOIN pedidos p ON c.id = p.cliente_id
ORDER BY p.fecha DESC;

2. Muestra el producto más vendido (nombre y cantidad total vendida) usando SUM y GROUP BY.

SQL
SELECT pr.nombre, SUM(dp.cantidad) AS total_vendido
FROM detalle_pedidos dp

Proyecto 2: Blog

Un sistema de blog donde los usuarios pueden escribir posts, categorizarlos y recibir comentarios. Este proyecto cubre relaciones de uno a muchos y consultas con múltiples JOINs.

Diagrama textual

usuarios (1) ──── (N) posts (N) ──── (N) categorias
  └── (1) ──── (N) comentarios ──── (1) posts
SQL - Creación del esquema
CREATE TABLE usuarios (
  id INT PRIMARY KEY AUTO_INCREMENT,
  nombre VARCHAR(60) NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  fecha_registro DATE DEFAULT (CURDATE())
);

CREATE TABLE categorias (
  id INT PRIMARY KEY AUTO_INCREMENT,
  nombre VARCHAR(50) NOT NULL
);

CREATE TABLE posts (
  id INT PRIMARY KEY AUTO_INCREMENT,
  titulo VARCHAR(150) NOT NULL,
  contenido TEXT NOT NULL,
  usuario_id INT NOT NULL,
  categoria_id INT,
  fecha_publicacion DATETIME DEFAULT NOW(),
  FOREIGN KEY (usuario_id) REFERENCES usuarios(id),
  FOREIGN KEY (categoria_id) REFERENCES categorias(id)
);

CREATE TABLE comentarios (
  id INT PRIMARY KEY AUTO_INCREMENT,
  contenido TEXT NOT NULL,
  usuario_id INT NOT NULL,
  post_id INT NOT NULL,
  fecha DATETIME DEFAULT NOW(),
  FOREIGN KEY (usuario_id) REFERENCES usuarios(id),
  FOREIGN KEY (post_id) REFERENCES posts(id)
);

Consultas para resolver

1. Lista todos los posts con el nombre del autor y la categoría usando INNER JOIN.

Ver solución
SQL
SELECT p.titulo, u.nombre AS autor, c.nombre AS categoria, p.fecha_publicacion
FROM posts p
INNER JOIN usuarios u ON p.usuario_id = u.id
INNER JOIN categorias c ON p.categoria_id = c.id
ORDER BY p.fecha_publicacion DESC;

Proyecto 3: Gestión Escolar

Un sistema para gestionar estudiantes, cursos, profesores y matrículas. Este proyecto cubre relaciones muchos a muchos y consultas complejas con múltiples tablas.

Diagrama textual

estudiantes (N) ──── (N) cursos (N) ──── (1) profesores
       └── a través de matriculas ──┘
SQL - Creación del esquema
CREATE TABLE estudiantes (
  id INT PRIMARY KEY AUTO_INCREMENT,
  nombre VARCHAR(60) NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  fecha_nacimiento DATE,
  grado VARCHAR(20)
);

CREATE TABLE profesores (
  id INT PRIMARY KEY AUTO_INCREMENT,
  nombre VARCHAR(60) NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  especialidad VARCHAR(50)
);

CREATE TABLE cursos (
  id INT PRIMARY KEY AUTO_INCREMENT,
  nombre VARCHAR(80) NOT NULL,
  descripcion TEXT,
  profesor_id INT,
  FOREIGN KEY (profesor_id) REFERENCES profesores(id)
);

CREATE TABLE matriculas (
  id INT PRIMARY KEY AUTO_INCREMENT,
  estudiante_id INT NOT NULL,
  curso_id INT NOT NULL,
  fecha_matricula DATE DEFAULT (CURDATE()),
  calificacion DECIMAL(4,2),
  FOREIGN KEY (estudiante_id) REFERENCES estudiantes(id),
  FOREIGN KEY (curso_id) REFERENCES cursos(id)
);

Consultas para resolver

1. Lista los estudiantes con los cursos en los que están matriculados, incluyendo el nombre del profesor que imparte cada curso.

Ver solución
SQL
SELECT e.nombre AS estudiante, c.nombre AS curso, p.nombre AS profesor, m.calificacion
FROM estudiantes e
INNER JOIN matriculas m ON e.id = m.estudiante_id
INNER JOIN cursos c ON m.curso_id = c.id
INNER JOIN profesores p ON c.profesor_id = p.id
ORDER BY e.nombre, c.nombre;

2. Calcula el promedio de calificaciones por cada curso, ordenado de mayor a menor promedio.

Ver solución
SQL
SELECT c.nombre AS curso, ROUND(AVG(m.calificacion), 2) AS promedio, COUNT(m.id) AS estudiantes
FROM cursos c
INNER JOIN matriculas m ON c.id = m.curso_id
GROUP BY c.id, c.nombre
ORDER BY promedio DESC;
